# 09 — FDE Learning Track (Ashwa as a training ground)

Status: v0.1. A Forward Deployed Engineer (FDE) sits with customers, finds the real problem, ships working software fast in their environment, and turns field insight into product. Ashwa's pilot works the same way, so log it as evidence.

| FDE competency | Ashwa practice | Evidence to keep (portfolio) |
|---|---|---|
| Problem discovery on site | Field visits at pickup time (`08` P3) | Field notes → conjectures |
| Decomposing messy workflows | Map the driver's day minute by minute | Workflow diagram |
| Shipping fast in a constrained environment | Low-end Android, patchy data, Kannada UI | Release notes, before/after metrics |
| Data and integrations | OTP provider, push/FCM, maps, WhatsApp deep links, Postgres/Prisma | Architecture note + trade-offs |
| Production reliability | Alerts delivered ≥95%; incident protocol | Monitoring dashboard screenshot, postmortems |
| Stakeholder communication | Explain the app to drivers, parents, a principal | Message templates, demo video |
| Writing | Bet cards, memos, this folder | The repo itself |
| Measuring impact | Calls/day, activation %, penetration % | Weekly metrics posts |
| Using AI to go faster | Agent-assisted coding, translation, note summarising | Prompt and workflow notes |

3. A trade-off I made under a constraint (cost, device, language).
